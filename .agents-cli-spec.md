# Agent Spec — Video Face Grab Agent

## Overview
An ADK agent for **Gemini Enterprise (Gemini Agent)** that accepts an uploaded video file (via direct chat paperclip attachment or a `gs://` Cloud Storage URI), detects and clusters every discernable forward-facing human identity across the video using RetinaFace + ArcFace (`insightface`), selects the single clearest frame for each person, uploads lossless `.png` pairs (`person_XX_face_crop.png` and `person_XX_full_frame.png`) to Google Cloud Storage (`gs://video-face-grab-faces/<video-stem>-<unique-suffix>/`), and renders **both the cropped face and full video frame inline** in the Gemini Enterprise UI alongside a clarity breakdown table.

## Language
`python`

## Example Use Cases
1. **Direct Chat Video Attachment**:
   - **Input**: User attaches `interview.mp4` in Gemini Enterprise and prompts: *"Grab all forward-facing faces from this video."*
   - **Output**: The agent intercepts the attached video artifact, runs `extract_forward_facing_faces`, saves each person's `face_crop.png` and `full_frame.png` as ADK session artifacts and to `gs://video-face-grab-faces/interview-<suffix>/`, and responds with inline images of every detected person's cropped face and full frame plus a clarity metrics table.
2. **Cloud Storage (`gs://`) Video URI**:
   - **Input**: *"Extract the clearest forward-facing frames for each person in `gs://video-face-grab-faces/uploads/keynote.mp4`."*
   - **Output**: The agent downloads the video from GCS to a temporary workspace, runs the face clustering and pose-filtering pipeline, uploads the resulting PNG sets to `gs://video-face-grab-faces/keynote-<suffix>/`, and displays both the face crop and full frame inline per person.

## Tools Required
1. `extract_forward_facing_faces(video_source: str, tool_context: ToolContext) -> dict`:
   - Accepts an ADK artifact filename (e.g., `"attached_video.mp4"` or `"auto"` to pick the latest attached video in the session), a `gs://bucket/object` URI, or a local test path.
   - Runs `VideoFaceProcessor` (RetinaFace + 512-D ArcFace clustering + 3D frontal pose filter + composite clarity scoring).
   - Uploads `person_XX_face_crop.png` and `person_XX_full_frame.png` to `gs://video-face-grab-faces/<folder>/`.
   - Saves both PNGs per person into the ADK session `ArtifactService` (`await tool_context.save_artifact(...)`) and returns inline renderable URLs (V4 Signed URL or `/api/storage/<folder>/<file>.png` proxy) plus clarity metrics.
2. `list_uploaded_video_artifacts(tool_context: ToolContext) -> dict`:
   - Lists video artifacts attached in the current conversation session.

## Constraints & Safety Rules
- **Forward-Facing Pose Enforcement**: Must skip side-profile faces (`yaw_asymmetry > 0.42` or nose outside eyes) and downward/upward-pitched faces (`nose_ratio` outside `[0.36, 0.59]`).
- **1 Person = 1 Best Frame Set**: Must consolidate split clusters via `_consolidate_clusters()` so a single person is never duplicated across camera cuts.
- **No Raw Video Token Bloating**: `before_model_video_interceptor` must save incoming `video/*` `inline_data` blobs to ADK `ArtifactService` and replace the binary blob in `llm_request.contents` with a lightweight text reference before calling the LLM.
- **Path & Bucket Safety**: Only read local files from approved temporary/workspace paths and enforce path-traversal guards on all folder and file names.

## Success Criteria
1. **Unit & Integration Suite (`pytest`)**: 100% pass rate covering sharpness, 3D pose filtering, cluster consolidation, ADK artifact extraction, `gs://` URI extraction, and `/api/storage/{folder}/{file}` image proxy rendering.
2. **Benchmark Video Parity (`test-video-face-grab.mp4`)**: Running the agent on `test-video-face-grab.mp4` detects exactly 2 forward-facing people (`Person #01` at `0.33s` and `Person #02` at `21.0s`), saves 4 PNG session artifacts (`2 people × 2 PNGs`), and returns inline Markdown images for both cropped faces and full frames.
